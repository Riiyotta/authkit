# AuthKit clone — information architecture

Local pixel-fidelity clone of `https://www.authkit.com/`.
React 18 + Vite 5 + Tailwind v3. Dev server: `npm run dev` → http://localhost:5191/

## Files

| file | status |
|---|---|
| `ia.json` | **hand-edited — the only source of truth** |
| `IA.md` | generated by `build.mjs` — do not edit |
| `matrix.csv` | generated by `build.mjs` — do not edit |
| `validate.mjs` / `build.mjs` | generic scripts, copied in as-is |
| `CLONE_SPEC.md` / `ASSETS.md` | upstream measurement of the original (recon output) |

Re-run after editing `ia.json`:

```bash
node validate.mjs && node build.mjs
```

## What the data actually shows

**This is a one-route site, and that is a measured fact rather than a scoping
choice.** The original has no `sitemap.xml` and no `robots.txt`, every `href`
in the page points off-domain, and 15 probed candidate routes (`/docs`,
`/pricing`, `/blog`, `/about`, `/login`, `/signup`, `/features`, `/security`,
`/changelog`, `/legal`, `/privacy`, `/terms`, `/contact`, `/customers`,
`/enterprise`) all return 404. Only `/` returns 200.

**Read the "0 shared sections · 18 page-local" line with that in mind — it is
an artifact, not a finding.** Section-level reuse is undefined when there is
exactly one template: every section is trivially single-use, so the metric
carries no signal here and should not be read as "keep all 18 page-local".

**The real reuse signal sits one level below the section layer, in the shared
primitives** — and that layer is genuinely shared:

| primitive | section files | render sites |
|---|---:|---:|
| `OutlineBox` | 4 | 8 |
| `GlowingButton` | 4 | 5 |
| `AuthCard` | 2 | 4 |
| `SectionHeader` | 4 | 4 |
| `BetweenLines` | 2 | 2 |

`AuthCard` is the one worth noting: a single component renders all four
sign-in card previews (three mapped in the hero, one as the customiser
target). It was four inline copies after the first build pass and was
consolidated deliberately.

**Chrome is almost absent.** The whole site is `chrome = minimal-static`:
there is no `<nav>` and no `<footer>` element, and the hero header is
`position: static` with no sticky, blur or scroll behaviour. The only
inter-section furniture is a 1px rule, and it appears at just 4 of the 8
section boundaries.

**Two of eighteen sections are actually interactive** — the hero light switch
and the 12-button customiser. The other five `PRODUCT_DEMO` sections are
observer-triggered animation sequences with no user input.

## Known deviations from the original

- **Fonts.** The original uses Untitled Sans (Klim) and Aeonik Pro (CoType),
  both commercial licences served from the WorkOS CDN. This clone self-hosts
  metric-matched substitutes (Inter / Instrument Sans / Share Tech Mono) with
  the original's own `local(Arial)` metric-override `@font-face` blocks. Every
  numeric type value matches exactly; only glyph-level text-run widths differ
  (0.1–13px). Swapping in licensed files is a token-level change.
- **All outbound links are inert `#`.** Every off-domain destination was
  removed by request, and every asset resolves to a local file under
  `public/`, so the clone runs fully offline.
- **Document height is not a fidelity metric here.** Sections use
  `content-visibility: auto`, so `scrollHeight` varies between passes on both
  the clone and the original; both read 7646px on matched fully-expanded
  passes at 1280px.

## Validator notes (informational, not failures)

`validate.mjs` flags two sections whose `scope` prose contains numbers that
differ from the computed route count. Both are correct as written: the numbers
describe **component instances and section boundaries**, not routes
(`chrome.page-separator` — 4 of 8 boundaries; `hero.auth-card-trio` — 4
instances site-wide). On a single-route site every computed route count is 1,
so any quantity in prose will trip this check.

## Brand content

The AuthKit/WorkOS wordmarks, customer logos, testimonial headshots and
marketing copy are reproduced from the original for local fidelity. They are
third-party brand assets — replace them before this is published or used
anywhere outward-facing.
